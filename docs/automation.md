# Automation

This repository holds only what is needed to build and verify. Matching tools (draft generators, judges,
permuter wrappers) and any agent orchestration run from outside it and treat it as follows.

- **The repo is the single source of truth and has one writer.** Candidates are compiled and compared in a
  scratch directory outside the repository. A candidate that scores zero differences is still only a candidate.
- **Integration** means: copy the source to `src/auto/<symbol>.c|.cpp`, add its block to
  `config/usa/arm9/delinks.txt` in address order, run `venv/bin/python tools/match.py verify`, and commit only on
  `VERIFY PASSED`. One commit per function: `Reconstruct <symbol> as matching natural C` (or `C++`).
- **Progress** is regenerated by `venv/bin/python tools/match.py progress` in a separate commit.
- **Shared matching tools** come from [DS Decomp Studio](https://github.com/liolu/ds-decomp-studio)
  (`gametools/`): `auto_match.py` (mass m2c drafts kept only when they compile to a match), `candidate_judge.py`
  (scratch-only judge), `gen_context.py` (prototype header), `find_culprits.py` (which file broke the ROM). They
  run with the working directory set to this repository, or with `DSD_PROJECT` pointing at it.
- **Optional third-party tools** go in ignored folders: `tools/m2c/`, `tools/decomp-permuter/`, `tools/mwccarm/`.

Things a judge cannot see and only the full ROM build catches: a reference to the wrong data symbol, extra
sections emitted by C++ constructs (`.ctor`, `.init`, vtables, exception tables), and literal placement.
