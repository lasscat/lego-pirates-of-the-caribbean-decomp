# Agent contract

Matching decompilation of LEGO Pirates of the Caribbean DS (USA, `BZDE`). Build and verify tools live in `tools/`.

## Non-negotiable gates

- Only unchanged `venv/bin/python tools/match.py verify` printing `VERIFY PASSED` with ROM SHA1
  `0a83684764a1a2c1cd16442f42891eb6c2affa46` proves a match. Masked compares, objdiff percentages and judge
  scores are diagnostics, never counts.
- Never weaken or bypass: global compiler/linker flags, the verifier, the `.sha1` file, `config/usa/compilers.txt`
  rows that exist, or the policy checks. Do not change a global flag to make one function match.
- Natural clean-room C/C++ only, written from the binary and public documentation. No leaked source. ASCII only
  in `src/` and `include/`. No opcode transcription, raw machine-code arrays or naked-function escape hatches.
- Exceptions must be marked where they occur (see `docs/exceptions.md`): `// FAKE: <reason>` for steering
  constructs and last-resort `volatile`, `// ASM: <reason>` above a hand-written `asm` function. Assembly needs
  explicit human approval per source file.
- Never commit ROMs, BIOS files, `extract/`, `build/`, tool binaries or anything derived byte-for-byte from a
  ROM. Stage exact paths; never `git add .`, `git add -A` or `git add -u`.
- Commits are author-only (no co-author trailers). Pushes are fast-forward only; never force-push.

## Source layout

- One function per file: `src/auto/<symbol>.c` or `.cpp`, plus its block in `config/usa/arm9/delinks.txt`
  (`complete`, exclusive `.text` range, blocks kept sorted by `start:`). Never overlap two owners, and never leave
  a `.c` and a `.cpp` with the same basename.
- Language is chosen by extension, exactly one `-lang` per compile. Read `docs/cpp.md` before adding C++
  constructs: declaration-only classes, no accidental vtables, RTTI or static initialisers.
- The compiler profile is in `game.toml` and `docs/compiler.md`; per-file differences go in
  `config/usa/compilers.txt`.
- `config/usa/tu_map.tsv` says which original source file a function belonged to. Names follow `docs/names.md`.

## Working rules

- One coordinator owns shared writes and builds. Reconstruction work happens in a scratch directory outside the
  repo and is judged there; nothing edits the repo while that work is running.
- Integrate, then run the full verify, then commit. On a failed verify stop and keep the evidence.
- README progress is generated by `tools/match.py progress` in its own commit. Do not hand-edit it.
